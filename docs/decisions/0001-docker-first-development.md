# 1. Docker-first Development Environment

* Status: Accepted
* Date: 2026-08-28

## Context
We need to guarantee an identical development environment across different machines, CI pipelines, and Codex agent setups, without relying on specific versions of Ruby or PostgreSQL installed on the host OS.

## Decision
We adopt a **Docker-first** approach:
- The project runs exclusively via Docker containers managed by Docker Compose.
- The original `Dockerfile` generated by Rails is preserved strictly for production use.
- A custom `Dockerfile.dev` is used for the local development environment.
- PostgreSQL runs isolated within Compose's internal network using version `17.10-bookworm`.

## Consequences
- The host machine only requires Docker Engine, Docker Compose, and Git.
- All Rails/Ruby commands must be executed via `docker compose run` or `exec`.
- Isolation eliminates the "works on my machine" problem.
